# 节选示范：结论先行 + 公司脉络开场

> **已脱敏**：公司名、产品名、合作方、具体数字均已替换为占位内容，**结构、句式、加粗位置、论断推进逻辑保持原样**。目的是示范「怎么写」，不是提供素材。
> 源出三份样本报告（Manus / World Labs / 无涯智远×超衍智能）的共通写法。

## 一、结论先行（`.thesis`）

这是全文最重要的一块。注意**论断的推进顺序**：定性 → 位置 → 资产 → 独有条件 → 走向。

```html
<section class="thesis" id="thesis" style="border-top-width:2px">
  <h2>结论先行</h2>
  <ol>
    <li><b>Acme Labs 是一家独立公司，主体、产品与市场分属三层，不重合。</b>法律主体在 A 地、
        总部在 B 地、研发重心在 C 地与 D 地，产品面向全球公开发售，收入几乎全部来自海外；
        {某年某月}它宣布筹建面向国内市场的产品线，是把中国当作一个<b>新增市场</b>来做。
        这三层各自独立，读法不同结论会完全相反。</li>

    <li><b>它站在一条两头受挤的窄缝里，而在这个位置上站得住的公司本来就不多。</b>
        上游模型公司既卖铲子又亲自下场——{竞品}开源了同协议的 Agent harness，还配了 {N} 亿元融资；
        下游超级 App 把免费当入口——{竞品}免费版送积分。可是在这个位置上，
        <b>收入成型、面向全球发售、既不隶属模型公司也不隶属超级 App 的通用 Agent，
        公开信息里很难找到第二家。</b></li>

    <li><b>它的技术资产确实在被商品化，而它此前几次站住脚，靠的也不只是技术资产。</b>
        跨模型的工程能力现在有了免费的开源替代，<b>这一点必须承认</b>。
        但那条尺子——<b>1 元 token 成本要带回 10 元收入</b>——考的是交付价值而非技术稀缺性：
        新版把单任务成本降了 32%、时间降了 28.2%，同时把产品线推向交付物本身值钱的场景。
        它是在按这条尺子的方向走，<b>只是还没公开交卷</b>。</li>

    <li><b>它有两项短期内不容易被复制的条件。</b>一是 {位置条件}——同时满足这三个条件的
        产品很少；二是 {经历条件}——具备同等完整经历的公司很少。</li>

    <li><b>较为合理的活法可能不是争通用入口，而是继续做深交付。</b>{产品}已经指向的方向
        ——重执行、高交付物价值的场景——恰好是免费锚点较难覆盖的部分。</li>
  </ol>
</section>
```

### 逐条拆解：每一步在干什么

| 条 | 作用 | 关键手法 |
|---|---|---|
| 1 | **定性 + 拆层** | 指出"三层不重合"，并给出**读错会得出相反结论**的警告。开篇就建立分析框架 |
| 2 | **定位** | 上游+下游同时受挤，然后一句反证：「很难找到第二家」——**用稀缺性代替形容词** |
| 3 | **主动认短板** | 「这一点必须承认」——**先承认，再给出为什么仍然成立的理由**。不承认短板的报告不可信 |
| 4 | **给出独有条件** | 用「同时满足三个条件的产品很少」这种**交集句式**，比"有护城河"具体 |
| 5 | **给走向** | 用"较为合理的活法可能是…"——**推测语气 + 具体方向**，不是"前景广阔" |

### 值得偷的几个句式

- 「**三层各自独立，读法不同结论会完全相反。**」——把"为什么值得细看"讲清楚
- 「**公开信息里很难找到第二家。**」——稀缺性断言，可被证伪
- 「**这一点必须承认。**」——主动认短板，紧接着「但…」转折
- 「**只是还没公开交卷。**」——区分"方向对"和"已验证"
- 「**较为合理的活法可能是…**」——推测而不是断言

### 反例对照

> ❌ Acme Labs 是一家优秀的 AI Agent 公司，团队实力强劲，技术领先，在全球化布局上走在前列，发展前景广阔。

问题：全是形容词，**没有一句可被证伪**，读者读完不知道这家公司到底站在哪、危险在哪。

## 二、公司脉络开场（`p.lede`）

```html
<section id="premise">
  <span class="snum">01</span>
  <h2 class="sec">先把它是谁、卖什么、卖给谁说清楚</h2>

  <p class="lede">关于这家公司的一种常见误读，是把"主体在哪、产品卖到哪、收入来自哪"
     三件事混成一件。这三层在 Acme Labs 身上是分开的，而<b>分开本身不是缺陷</b>，
     是它做全球化时形成的结构。</p>
```

**这一步的手法**：不写"公司成立于 X 年，总部位于 Y"这种百科式开场，而是**直接点名一个常见误读，然后纠正它**。

- 先立靶子：「一种常见误读是…」
- 再给纠正：「这三层是分开的」
- 最后**反转价值判断**：「分开本身不是缺陷，是结构」——把看似的弱点重新框定为设计

同一份报告里，这个开场被复用在 01 节的每一处：**先说别人会怎么读错，再说应该怎么读。**

## 三、写「组织人才」时的口径提醒

```html
<div class="callout">
  <div class="ct">口径提醒</div>
  <p>论文署名 ≠ 员工名单；在招岗位 ≠ 实际团队；合作网络 ≠ 汇报关系。</p>
</div>
```

只要报告里用了论文署名或招聘数据来推断组织，**就必须放这个 callout**。这不是免责声明，是把数据边界交给读者。

## 四、写「竞争格局」的收尾

三份样本报告在竞争一节**都以同一个动作收尾**：

```html
<div class="callout warnb">
  <div class="ct">它站的那条缝</div>
  <p>护城河建立在下游工程接缝上，而这条接缝的宽度取决于竞品愿不愿意做工程——
     <b>这是一条会随时间变窄的护城河。</b></p>
</div>
```

**要点**：不只说缝在哪，还要说**缝的宽度怎么变化、朝哪个方向变**。更进一步：如果收窄来自内部（如母公司承诺开源自家产品），**要点明"风险来自内部"**——这是最容易被忽略的一类。
