# 工作流详细展开

`SKILL.md` 里 8 阶段的展开版，重点是每步的**判断要点**和**常见坑**。

---

## 阶段 0 · 定题

**要定下来的五件事：**

| 项 | 说明 |
|---|---|
| 公司名 | 全称 + 常用简称。多公司合写用 `A × B` |
| slug | 小写连字符，如 `worldlabs`、`rsi-neolabs`。用于文件名 |
| 对象范围 | 一家还是多家。**可比公司合写一份更有价值**——对比本身就是分析 |
| 数据截止日 | 今天。写进 docmeta 和页脚 |
| 一句话核心问题 | standfirst，句式「为什么 X——这对 Y 意味着什么？」 |

**判断要点：核心问题必须是一个真问题。**
- ✅「一家把空间智能当独立技术路线做的实验室，为什么最终同意被芯片公司收购——这对它自己和整个 Neolab 群体意味着什么？」
- ❌「本文介绍 World Labs 的发展历程与业务模式。」

**常见坑：** 核心问题写成了内容摘要。检验方法——**这个问题有答案吗？答案是单一的吗？** 如果答案是"介绍完了"，就不是问题。

**动手写文件前**：按用户偏好确认交付路径与文件名。

## 阶段 1 · 公开信息采集

**六个面一次性铺开，不要一条条问用户。** 见 `sourcing-and-verification.md` 的速查表。

**判断要点：**
- **先宽后窄**。第一轮把所有面都扫一遍，形成骨架；第二轮针对结论先行要用的论断做定向补采。
- **来源即记**。边采边记 `标题 / 日期 / URL`，不要指望回头再找。
- **一手优先**。同一件事有官方公告和媒体报道时，用官方公告；媒体报道只在补充背景时用。

**常见坑：**
- 只搜中文名 → 漏掉英文官网/论文。**中英名都搜**（尤其是有海外背景的团队）。
- 把搜索结果摘要当来源。**摘要不是来源**，点进去看原文。
- 招聘页去抓人名和联系方式。**只看岗位分布**。

---

## 阶段 2 · 事实分层与核验

逐条打标：已核实 / 未核实存疑 / 推算 / 未能获取。详见 `analysis-frameworks.md` 第 1–3 条。

**判断要点：**
- **先找反证**。对每个顺理成章的结论，主动搜一次"反面证据"。
- **口径冲突就是发现**。两个指标指向相反时，不要挑一个，那正是最有信息量的地方。
- 拿不到就是拿不到。**「未能获取」写进报告，比含糊过去有价值。**

**常见坑：** 把"多方报道一致"当成"已核实"。多个媒体转述同一个未署名信源，仍然是未核实。

---

## 阶段 3 · 组织与人才

**判断要点：**
- **组建逻辑比人数有信息量。**
  - *学术网络型*：班底来自某个实验室，核心论文作者全是组内学生，外部只挂国际合作者 → 做的是研究问题
  - *产业回流型*：从大厂买人，但官网 Team 页可能**至今无具名负责人** → 做的是工程问题
- **招聘岗位分布是战略信号**。产品岗为 0 说明还没到产品化阶段；算法岗扎堆说明还在冲技术。
- 学术体量用引用数和 h-index 量化，用 `.bars` 对比。**注意学术体量与资本定价可能反向**——这本身就是洞察。

**常见坑：** 把论文署名当员工名单。署名包含外部合作者，也可能包含非研发角色。**必须放口径提醒 callout。**

---

## 阶段 4 · 技术路线

**判断要点：**
- **先定位层级，再谈技术。** 用 `.stack` 图把公司钉在栈的某一层。这一步能直接回答"它和谁是竞品"。
- **用对方自己的分类法。** 优先采用该公司自己提出的 taxonomy，而不是外部贴的赛道标签。这样能识别出"名字像竞品、其实不在一个类别"的公司。
- **技术分野要具体**。不说"技术领先"，说"交付的是可导出的 Gaussian splat、mesh，以及给物理引擎用的 collider mesh，而竞品交付的是可交互的生成结果"。

**常见坑：** 堆技术名词。**每一句技术描述都要落到"所以它的客户是谁 / 天花板在哪"。**

---

## 阶段 5 · 资本结构

**判断要点：**
- **投资方性质组合 > 金额大小。** 市场化组合（头部 VC + 产业方）vs 被地方国资同时"接住"，是两个完全不同的故事。
- **轮次金额未披露是常见情况**，如实写，不要用估值反推。
- 退出路径要区分**已宣布 / 已签署 / 已交割**。
- **战略收购的溢价不等于赛道验证**（见 `analysis-frameworks.md` 第 3 条）。

**常见坑：** 把估值当收入证据。估值是资本对未来的定价，含战略溢价。

---

## 阶段 6 · 竞争格局

三面固定，落点是那条缝。详见 `analysis-frameworks.md` 第 4 条。

**判断要点：**
- 上游要找**股东与对手重叠**的关系。
- 横向要用分类法筛掉伪竞品。
- 下游要回答**为什么可能自建**，不是客户名单。
- 落点必须是「这条缝会不会变窄」+「往哪个方向变」。

**常见坑：** 写成竞品清单。清单没有分析价值。

---

## 阶段 7 · 发展走向

四块：路径 / 信号 / 风险卡 / 上限推演。详见 `analysis-frameworks.md` 第 5–6 条。

**判断要点：**
- 路径要**分支式**，每条写触发条件，不预设单一结论。
- 信号要**前瞻**，每条附"为什么它领先"。
- 风险卡按**影响程度**排序，开头声明这一点。
- 上限推演回答"即使一切顺利，天花板在哪，受什么约束"。

**常见坑：** 风险写成概率表；预测没有可证伪性。

---

## 阶段 8 · 成文与交付

1. **先写结论先行。** 这一步会暴露你的证据够不够——写不出 4 条有证据的论断，说明阶段 1–2 没做够，回去补。
2. 按 `report-structure.md` 逐节展开。
3. 套 `templates/report-template.html`：把 `<style>` 块和骨架复制出来，逐段填。**不要改设计系统。**
4. 工作稿存 `<slug>-report.html`；包外壳存 `<slug>-share/index.html`。
5. 过 `checklist.md`。

**写作口吻：**
- 分析性、数字密集、句子短。
- **该承认的短板要承认**：「这里数据缺失」「这条是推测」「未能获取」。
- 不用营销词（"赋能""颠覆""领先"）。不用"我们认为"——直接说结论和依据。
- **加粗要能独立成句**：只读加粗部分，逻辑应该完整。

## 明确不做（v1 边界）

| 不做 | 为什么 |
|---|---|
| 转公众号（PNG 出图、封面、draft 上传） | 下游独立流程，另有工作流 |
| 出 PDF | 需要额外工具链，破坏"不依赖终端"约束 |
| 抓登录墙数据 | 隐私与合规边界 |
| 任何装包 / 跑脚本 | 破坏跨终端可用性 |

这些都由 agent 结合具体情况人工处理，不在本 skill 范围内。
