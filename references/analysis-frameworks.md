# 分析框架

这套方法是这套报告区别于"搜一圈然后总结"的地方。六个框架，每个都对应一个具体的失败模式。

---

## 1. 事实分层（对应失败模式：把推断写成事实）

**每一条关键信息，在写进报告之前先归类：**

| 层级 | 标记 | 要求 |
|---|---|---|
| 已核实 | 附一手链接 | 官方公告 / 官方博客 / 融资披露 / 财报 / 论文原文 / 本人公开表述 |
| 未核实存疑 | 写明存疑理由 | 媒体转述、二手引用、时间对不上、多方说法冲突 |
| 推算 | 写明算法与假设 | 「按 70 人估算」——把分子分母都写出来 |
| 未能获取 | 写明障碍 | 登录墙 / 未披露 / 机器人拦截 |

**执行要点：**
- 报告里**不许出现没有归类的关键数字**。
- 第七节《哪些是事实，哪些还需要打问号》是这套纪律的落地处，不是可选项。
- 「未能获取」是一个**合格的结论**，不是失败。含糊带过才是失败。

**典型失败**：某公司估值数字来自一篇转述报道，报道本身引用"据知情人士"。→ 归入"未核实存疑"，并写明"未找到一手披露"。

---

## 2. 不继承搜索摘要的评判（对应失败模式：把别人的结论当自己的）

**搜索结果的自动摘要经常带评判性措辞**：「掉队」「已经跑出来了」「被淘汰」「掉出第一梯队」。这是聚合器在替你做判断，**不是数据**。

**规则：**
- 摘要里任何**结论形状**的短语，一律视为未核实。
- 要下这个判断，就去拿一手数据：官方公告、财报、融资披露、产品定价页、GitHub 活跃度。
- 拿不到一手数据 → **明写"未能获取"**，不要换个说法把摘要的判断重述一遍。

**真实教训**：曾有一次分析中，搜索摘要称某模型公司"掉队"。直接采信后被打回。核查发现：C 端 MAU 确实从约 3,600 万跌到约 830 万，但**是主动砍掉约 7 亿/年买量**的结果，同期 ARR 从 1 亿美元涨到 3 亿美元（API 占收入 70%+），估值半年涨 7–8 倍。
**同一个事实，用 MAU 衡量是"掉队"，用 ARR 衡量是"转型成功"。** 摘要选了前一个口径并把它说成了事实。

---

## 3. 口径冲突并列（对应失败模式：用单一指标下结论）

当多个指标指向不同方向时，**全部列出，并说明各自衡量什么**。不要择一。

| 指标 | 衡量的是 |
|---|---|
| MAU / DAU | C 端注意力，可被买量放大，也可被主动放弃 |
| ARR / 收入 | 实际付费意愿 |
| 估值 | 资本对未来的定价，含战略溢价，不等于商业模式验证 |
| 融资金额 | 投资方结构信息 > 公司健康度信息 |

**规则**：报告里出现「下降」「增长」这类词时，**必须紧跟口径**。写「MAU 下降」而不是「用户下降」。

**特别提醒**：估值上涨 ≠ 商业模式跑通。战略收购的溢价反映的是买方的竞争位置需求，不是标的的收入能力。这类交易**不构成赛道验证**。

---

## 4. 「它站的那条缝」（对应失败模式：把竞争写成竞品清单）

不要罗列竞品，要回答：**这家公司站在谁的缝隙里，这条缝有多宽，会不会变窄。**

三面固定：

- **上游** —— 供给方。**关键洞察：上游常常同时是股东与对手**（芯片公司投资模型公司，同时自己做大模型；云厂商是客户也是竞品）。
- **横向** —— 同类。**用研究对象自己提出的分类法**判断谁是真对手。行业标签会骗人：两个都叫"世界模型"的公司，可能一个做渲染器一个做规划器，根本不在一个类别。
- **下游** —— 客户。**核心问题是"为什么客户可能自建"**，而不是"客户是谁"。

**落点句式**：「护城河建立在下游工程接缝上，而这条接缝的宽度取决于竞品愿不愿意做工程——**这是一条会随时间变窄的护城河**。」

**还要看方向**：缝隙收窄可能来自外部（竞品降价、开源），也可能来自内部（母公司承诺开源自己的产品）。**来自内部的风险最容易被忽略。**

---

## 5. 风险卡：按影响程度排序，不按概率（对应失败模式：风险清单变成概率表）

**排序依据是「对'这件事是否被正确理解'的影响程度」，不是发生概率。**

理由：读者读风险一节是为了**避免误判**，不是为了做期望值计算。一条概率低但一旦发生就颠覆全文结论的风险，比一条概率高但无关痛痒的风险重要得多。

每张卡：
- `R1`..`Rn` 编号
- 标题写成**一个会被误读的命题**，例如「把交割前的宣布当成已经完成的事实」
- `.meter` 五格给强度（这是"影响程度"不是"概率"，可在卡前统一说明）
- 正文加粗**最容易被误读的那句话**
- 允许指出风险来自内部（如"压价的将不再只是竞争对手，还包括自己的母公司"）

---

## 6. 该盯的信号 + 上限推演（对应失败模式：给出没有可证伪性的预测）

**该盯的信号**：给**领先指标**，每条附「为什么它前瞻」。
- ✅「下游客户是否开始招仿真工程师——招人比发布产品早 2–3 个季度」
- ❌「预计 2027 年收入达到 X」

**上限推演**：回答「**如果一切顺利，能到哪**」——这是给乐观情形画天花板，并说明**天花板受什么约束**（市场规模、母公司战略、技术路线天花板）。
它的作用是让读者知道：**即使所有好事都发生，上限在哪。** 这比预测"会发生什么"有用得多。

---

## 组合使用

一份报告的分析力，来自这六个框架的组合：

```
事实分层 ──→ 保证每个数字可追溯
不继承摘要 ──→ 保证判断是自己的
口径并列 ──→ 保证不被单一指标带偏
那条缝   ──→ 把竞争从清单变成结构
风险卡   ──→ 把风险从概率变成误判防御
信号+上限 ──→ 把预测变成可证伪的观察
```
