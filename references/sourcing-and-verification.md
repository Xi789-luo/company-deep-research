# 来源、核实与隐私

## 来源层级

**T1 一手（可直接引用、可标"已核实"）**
- 官方公告 / 官方博客 / 技术报告 / 白皮书 / 产品定价页
- 创始人公开信、官方访谈、播客原始文字稿
- 融资披露（公司公告、投资方公告、SEC 文件、工商变更公开页）
- 论文原文（arXiv / HF / 期刊）、Google Scholar 公开引用数据
- 官网招聘页（只看**岗位分布**，不抓人名联系方式）

**T2 二手（需交叉验证，默认标"未核实"）**
- 媒体报道、行业分析、转述引用
- 第三方数据库（Crunchbase 等）——注意其数据常滞后或有误
- 社交平台讨论、论坛爆料

**T3 不可用（明确不采）**
- 搜索结果自动摘要里的**评判性结论**（见 `analysis-frameworks.md` 第 2 条）
- 登录墙后的数据（猎聘 / 脉脉 / 付费数据库）
- 任何需要绕过访问控制的来源

## 核实纪律

1. **每个进入报告的数字，都要能回答"它从哪来"。** 记不下来源的数字，就不要写。
2. **时间状语必须准确**：区分「已宣布 / 已签署 / 已交割 / 已上线 / 预计」。
3. **登录墙 / 机器人拦截 → 明写「未能获取」**，并说明障碍。**不要用二手转述假装拿到了一手。**
4. **冲突说法并列**，不要挑一个顺眼的。
5. **来源登记格式**：`标题，日期。URL`。日期必填——没有日期的来源无法判断时效。
6. **数据截止日**写进 `docmeta`，并在页脚重申。

## 隐私边界（硬约束）

**只采集本人已公开发布的职业信息：**
- ✅ 姓名、GitHub ID、提交数、雇主、教育背景、研究方向、公开主页链接、本人公开的邮箱
- ❌ 电话号码、微信号、私人社交账号
- ❌ 登录墙后的招聘平台数据
- ❌ 通过拼接多源信息推断出的私人联系方式

**为什么**：这些联系方式没有被当事人公开发布过，获取它们只能靠猜测或爬取非公开源。

**怎么处理**：相关列**留空**，并**一次性说明哪些列会为空、为什么**，然后继续。不要每次遇到都重新讨论。

**额外注意**：把对具名个人的评价（引用数、年龄、师承、能力判断）写进公开文档前，先问一句"这段会不会给当事人带来麻烦"。**内部研究报告与公开发布的内容，尺度不一样。**

## 抓取礼节

- 联网搜索与抓取是**只读操作**，连续、批量做完，不要每搜一条就停下来确认。
- 优先 WebFetch 官方页；需要结构化数据时用公开 API（arXiv / HF Papers / OpenAlex 等）。
- 不要高频请求同一站点。遇到限流就换源，不要重试轰炸。

