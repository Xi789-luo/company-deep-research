# 报告结构规范

## 骨架（8 段固定 + 3 段可选）

```
页眉   kicker / h1 / standfirst / docmeta
── 结论先行          .thesis          ★ 必写
01 公司脉络          它是谁、卖什么、靠什么收钱
02 组织人才          谁在做、怎么组织自己
03 技术路线          ★ 可选，可与 01 合并    它站在栈的哪一层
04 资本结构          ★ 可选，可与 01 合并    融资讲的是故事
05 竞争格局          上游 / 横向 / 下游 + 那条缝
06 发展走向          路径 / 信号 / 风险卡 / 上限推演
07 信息源与未核实项   已核实 / 存疑 / 未能获取
08 主要公开信息源     ol.src 编号列表
页脚   数据截止声明
```

**什么时候合并**：对象是小团队、公开信息少时，`03 技术路线` 和 `04 资本结构` 并进 `01 公司脉络`，全文压到 6 段。对象信息密度高（如 World Labs）时展开到 7–8 段。**段落数服从信息密度，不服从模板。**

**段号连续**：`01`–`0N` 按实际段数重排，不要在合并后留下空号。

---

## 页眉

- `kicker`：`公司深度研究 · {赛道} · {年份}`。赛道用行话，如「空间智能」「AI Agent」「RSI」。
- `h1`：公司名。多公司合写用 `A × B`。
- `standfirst`：**一句话核心问题**，句式「为什么 X——这对 Y 意味着什么？」。这是全文的钩子，必须是一个真问题，不能是内容摘要。
- `docmeta` 四项：数据截止 / 版本 / 核心结论 / 信息源。**「核心结论」是一句可以被证伪的断言**（如「技术路线成立，独立公司形态不成立」），不是「值得关注」这类废话。

---

## 结论先行（`.thesis`）

全文最重要的一块。**4–6 条，每条一个自然段。** 每条的结构固定：

> **加粗论断（一句话）。** 证据：数字、对比、时间线。**需要强调的是：{自我限定}。**

要点：
- **第一条必须是全文最反直觉的那个判断**，不是背景介绍。
- 论断之间要有推进关系：第一条定性 → 中间几条拆解（组织 / 资本 / 竞争）→ 最后一条给走向或结构性困境。
- 「需要强调的是」不是客套，是**主动标出这条判断的边界**：依据是什么、什么情况下不成立、哪个数字还没核实。**没有这一句的论断，就是没尽到责任。**
- 允许在论断里用 `<em>` 标出关键分类词（如 `<em>参数层</em>`），但每条最多一处。

反例（不要这样写）：
> ❌ 「该公司是一家优秀的 AI 公司，团队实力强，发展前景广阔。」

正例（结构正确）：
> ✅ 「**两家公司共享一个叙事，但站在这条技术栈的不同层上，不构成直接竞争。** A 做的是 <em>参数层</em>——让模型把新知识写进权重；B 做的是 <em>系统层</em>——让 AI 自己完成完整的研究闭环。把它们当成同一个赛道的对手来读，会读错。」

## 01 公司脉络

目标：**让读者知道这家公司靠什么活着。**

- 开场用 `p.lede`，一句话点出「这家公司最容易被误读的地方」。
- 紧跟一个 `.facts` 四格：选**最能定义这家公司的四个数字**（不是最漂亮的四个）。每格 `.fl` 必须写口径，例如「全股票对价」「按 70 人估算」。
- 然后按「它是谁 → 卖什么 → 卖给谁 / 靠什么收钱」展开，用 `h3` 切分。
- 至少一处 `blockquote` 直接引用官方或创始人的原话，`cite` 写明出处和日期。
- 有结构化数据就上 `.tw` 表格，`<caption>` 写口径和来源。

**「靠什么收钱」这一段不许含糊。** 如果确实没有公开收入信息，就明写「未公开收入，本报告不以估值代替收入证据」。

## 02 组织人才

- 创始团队：学术体量（引用数 / h-index，用 `.num`）+ 产业经历 + 师承，分开讲，不要混成一句「背景深厚」。
- 两人以上对比时用 `.bars` 做横向条形图，`.scale-note` 写明量纲。
- **组建逻辑**是最有信息量的角度：**学术网络型**（班底来自某个实验室，外部只挂国际合作者）vs **产业回流型**（从大厂买人，官网 Team 页却无具名负责人）。这两种逻辑对应公司做的是研究问题还是工程问题。
- 招聘岗位分布 → 战略重心信号（如「11 个在招岗位里产品与设计岗为 0」）。
- **必须放 `.callout` 口径提醒**：论文署名 ≠ 员工名单；在招岗位 ≠ 实际团队；合作网络 ≠ 汇报关系。
- 严守隐私边界（见 `sourcing-and-verification.md`）。

## 03 技术路线（可选）

- 先用 `.stack` 做**技术栈分层图**，把研究对象用 `.band.mid` 标出来。层与层之间用 `.membrane` 写衔接说明（谁供给谁、关键约束是什么）。
- 再讲旗舰成果时间线（用 `.tw` 或有序列表，标年月）。
- 最后讲**技术分野**：和谁像、和谁不像，差在哪。**优先采用该公司自己提出的分类法**（如 World Labs 的「渲染器 / 模拟器 / 规划器」），而不是外部强加的赛道标签——这样能识别出"看起来是竞品其实不是"的公司。

## 04 资本结构（可选）

- 轮次表用 `.tw`，列：轮次 / 时间 / 金额 / 投资方 / 性质。性质用 `.chip` 编码（`ok` 市场化 / `mid` 国资 / `no` 存疑）。
- **核心洞察是投资方的性质组合，不只是金额**：市场化组合（红杉 + 联想之星）vs 被三地国资同时"接住"，讲的是两个完全不同的故事。
- 讲清股权、控制权、退出路径。退出路径要区分「已签署」和「已交割」。

## 05 竞争格局

固定三面，用 `h3` 分开：

1. **上游** —— 谁供给它。**关键洞察：上游常常同时是股东与对手。**
2. **横向** —— 谁在同一个类别里。用对方自己的分类法判断谁是真对手。
3. **下游** —— 客户为什么可能**自建**而不是采购。

收尾必须是 `.callout.warnb`「它站的那条缝」：这条缝有多宽、**会不会随时间变窄**、护城河朝哪个方向移动。三份样本报告都用这个落点。

## 06 发展走向

四块，顺序固定：

1. **可能的路径** —— 用 `.chips` 枚举 2–4 条分支，每条写触发条件。**分支式，不预设单一结论。**
2. **该盯的信号** —— `ul.plain`，每条是「信号 + 为什么它前瞻」。是**领先指标**，不是预测。
3. **主要风险** —— `.risk` 卡 R1..Rn。开头必须声明：**按「对判断的影响程度」排序，不按发生概率。** 每张卡的 `.meter` 五格给强度，`em` 给「高/中/低」。卡片正文里加粗那句最容易被误读的话。
4. **上限推演** —— 「如果一切顺利，能到哪」，以及天花板受什么约束。

## 07 信息源与未核实项

三小节，**这一节是这份报告可信度的全部来源**：

- **已核实（附一手来源）** —— 每条挂 `<a href>` 一手链接。
- **未核实 / 存疑** —— 每条写清「为什么存疑」+「什么能证伪它」。
- **未能获取** —— 想要但拿不到的数据 + **障碍是什么**（登录墙 / 未披露 / 机器人拦截）。**不许糊弄过去。**

## 08 主要公开信息源

`ol.src` 有序列表，自动编号 `01.` `02.`。每条：`标题，日期。<a href>显示文本</a>`。
显示文本用**去掉 scheme 的短形式**（`worldlabs.ai/blog/atlas`），不要贴一长串 URL。
按重要性或时间倒序，**不要求穷举，但要求覆盖结论先行里的每一条论断**。

## 页脚

数据截止声明 + 「所有推断均已标注核实状态；未标注来源的数字为公开报道口径，可能存在偏差」。
