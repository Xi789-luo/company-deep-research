# 交付前自检

逐条过一遍。**任何一条不过，就回去改，不要交付。**

## A. 内容可信度

- [ ] 结论先行的每一条论断，都有**具体证据**（数字 / 对比 / 时间线），不是形容词
- [ ] 每一条论断都有「需要强调的是…」式的**自我限定**
- [ ] 报告里**没有未归类**的关键数字——每个数字要么标了来源，要么标了"推算/存疑"
- [ ] 没有任何判断是从**搜索结果摘要**里继承来的（摘要里的"掉队""跑出来了"之类一律已回查一手源）
- [ ] 出现"下降/增长"时，**紧跟口径**（MAU？ARR？估值？）
- [ ] 冲突的口径是**并列呈现**的，没有择一
- [ ] 时间状语准确：宣布 / 签署 / 交割 / 上线 / 预计，各自用对
- [ ] 第七节写全了三类：已核实（附链接）/ 存疑 / 未能获取
- [ ] 「未能获取」的条目写明了**障碍是什么**
- [ ] 没有把推断写成事实

## B. 结构完整

- [ ] 页眉四项齐全：数据截止 / 版本 / 核心结论 / 信息源计数
- [ ] `standfirst` 是一个**真问题**，不是内容摘要
- [ ] `核心结论` 是一句**可被证伪的断言**，不是"值得关注"
- [ ] 段号 `01`–`0N` **连续无空号**
- [ ] 竞争一节的三面齐全：上游 / 横向 / 下游
- [ ] 竞争一节以「**它站的那条缝**」+「会不会变窄」收尾
- [ ] 风险卡开头声明了「**按影响程度排序，不按发生概率**」
- [ ] 有「该盯的信号」（前瞻指标，非预测）
- [ ] 有「上限推演」
- [ ] 来源列表覆盖了结论先行里的**每一条**论断

## C. 隐私与合规

- [ ] 没有任何电话号码、微信号、私人社交账号
- [ ] 没有引用登录墙后的数据
- [ ] 涉及具名个人的评价，措辞是**职业维度**的（引用数、履历），没有人身评价
- [ ] 若本报告会公开发布：已重新审视对具名个人的段落

## D. 设计系统

- [ ] `<style>` 块是**从模板原样复制的**，没有改配色 / 换框架
- [ ] 没有引入任何外部 CSS / JS 库
- [ ] 图表全部是 HTML/CSS（`.bars` / `.stack` / `.facts` / `.tw`），没有 `<img>` 图表
- [ ] 数字列用了 `class="n"`，行首标签用了 `class="k"`
- [ ] 表格有 `<caption>` 写口径
- [ ] `.facts` 每格 `.fl` 都写了口径
- [ ] `blockquote` 有 `<cite>` 写「出处，日期」
- [ ] `<em>` 用得克制（全文十来处以内）
- [ ] **只读加粗部分，逻辑完整**（这是最重要的排版检验）

## E. 交付形式

- [ ] 工作稿存为 `<slug>-report.html`
- [ ] 分享版存为 `<slug>-share/index.html`，含 `<!doctype html>` / `<meta charset>` / viewport / 字体 CDN link
- [ ] **断网打开分享版，版式不塌**（字体回落到系统字体即可）
- [ ] **手机上打开，无横向滚动条**（表格在 `.tw` 里横向滚动是正常的）
- [ ] 深色模式下打开一次，确认对比度正常

## F. 约束

- [ ] 没有创建任何脚本文件（`scripts/*.py` 等）
- [ ] 没有要求用户安装任何东西
- [ ] 没有修改用户机器上的配置 / 服务 / 定时任务

---

## 最常见的三种退回

1. **论断是形容词堆的**：「团队实力强、技术领先、前景广阔」→ 换成数字和对比。
2. **没有自我限定**：每条论断都写得斩钉截铁，读者无从判断边界 → 补「需要强调的是…」。
3. **风险按概率排**：把最可能发生的排前面，而不是最容易被误读的 → 重排。
